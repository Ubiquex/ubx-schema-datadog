# CLAUDE.md — ubx-schema-datadog

## What this is

The real, published schema snapshot for the Datadog provider — a frozen,
versioned `manifest.json` + `members/*.json` group, generated by
`ubx-provider-dynamic --generate-snapshot-group` from Datadog's own live v1/v2
OpenAPI specs, committed here (not release-only) so a reviewer sees the real
diff. A `[providers.datadog]` pin in `ubx` resolves against this repo's own
real GitHub Releases via `provider.AcquireSchema`. Coordinating repo:
`github.com/ubiquex/ubiquex`.

Four real members: `datadog`/`datadog_v2` (resource mode) and
`datadog_ds`/`datadog_v2_ds` (data-source mode) — two API versions, each in
both modes, all four resolved from two config entries in one real invocation.

## Repo-specific mechanics

- `.github/workflows/hash-watch.yml` — weekly cron + manual dispatch. Builds
  `ubx-provider-dynamic` from ITS OWN real, latest published release tag (not
  `main` HEAD — an untagged build stamps every regenerated snapshot with the
  meaningless `min_binary_version: "dev"`, UBI-194). Never auto-merges.
- `.github/workflows/publish.yml` — manual dispatch only, refuses to
  republish an existing tag. Verify a real release via `gh api
  repos/Ubiquex/ubx-schema-datadog/releases/tags/v<version>` after dispatch,
  not the workflow's own exit status.
- `manifest.json`'s own `exclude` table records a real, live precedence
  judgment (v1's own richer members win real collisions against v2) — kept in
  sync by hand with `ubiquex`'s own `[dynamic_provider_groups.datadog_all.exclude]`
  table; if that table changes, this one needs updating to match, or a real
  future collision fails loud here until it is.
